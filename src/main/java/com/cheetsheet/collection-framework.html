Java Collections Framework — Cheat Sheet

Concise reference of interfaces, common implementations, and frequently used methods. Edit freely — this is a single-file HTML you can copy/paste into slides or open in a browser.

Core: Collection<E>

Root interface — common methods
  • boolean add(E e) — add element
  • boolean remove(Object o) — remove first occurrence
  • boolean contains(Object o) — membership test
  • int size() — number of elements
  • boolean isEmpty(), void clear(), Object[] toArray()

List<E> / ArrayList

Ordered, indexed collection — allows duplicates
  • E get(int index), E set(int index, E e)
  • void add(int index, E e), boolean add(E e), boolean addAll(Collection)
  • E remove(int index), boolean remove(Object o)
  • int indexOf(Object o), int lastIndexOf(Object o), List<E> subList(int,int)
  • When to use: ArrayList for fast random access; avoid many mid-list inserts.

LinkedList<E> (List, Deque)

Doubly-linked — fast inserts/removals at ends
  • addFirst(E), addLast(E), getFirst(), getLast()
  • removeFirst(), removeLast(), pollFirst(), pollLast()
  • get(int index) (O(n) traversal) — use for small lists or when end operations dominate

Set<E> (HashSet / LinkedHashSet / TreeSet)

Unique elements — different implementations for order/lookup
  • boolean add(E), boolean remove(Object), boolean contains(Object)
  • HashSet — O(1) average ops, no ordering
  • LinkedHashSet — preserves insertion order
  • TreeSet — sorted order, O(log n) ops (uses Comparator or natural ordering)

Queue<E> / PriorityQueue

FIFO or priority-based ordering
  • boolean offer(E) vs boolean add(E) (offer doesn't throw when full)
  • E poll() — retrieve & remove head (null if empty)
  • E peek() — retrieve head without removing
  • PriorityQueue — orders by natural ordering or given Comparator

Deque<E> / ArrayDeque

Double-ended queue — use as stack or queue (preferred over Stack)
  • Head: addFirst/offerFirst, pollFirst/removeFirst, peekFirst/getFirst
  • Tail: addLast/offerLast, pollLast/removeLast, peekLast/getLast
  • Stack-style: push(), pop(), peek()

Map<K,V> (HashMap / LinkedHashMap / TreeMap)

Key-value pairs — different implementations for ordering & performance
  • V put(K key, V value), V get(Object key)
  • V remove(Object key), boolean containsKey(Object), boolean containsValue(Object)
  • Set<K> keySet(), Collection<V> values(), Set<Entry<K,V>> entrySet()
  • HashMap — average O(1) get/put, allows null key/value
  • LinkedHashMap — predictable iteration order (insertion or access order)
  • TreeMap — sorted by key, O(log n)

Most Useful Methods — Quick Drill (Interview Focus)

Memorize the signatures and complexity where relevant
  • ArrayList: get(int) O(1), add(E) amortized O(1), add(int,E) O(n)
  • LinkedList: addFirst/last O(1), get(index) O(n)
  • HashMap: get/put average O(1), worst O(n) (pathological), use good hashCode
  • Concurrent note: look into ConcurrentHashMap & thread-safe collections for production systems
  • Queue: offer/poll/peek vs add/remove/element differences on empty/full
  • Deque: prefer ArrayDeque over legacy Stack and over LinkedList for stack/queue usage where possible
